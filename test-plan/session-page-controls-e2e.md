# Session page controls E2E

Use a dedicated test conversation and record both its session reference and conversation ID. Use a disposable Relay database for destructive cases. Arrange server and extension updates during an idle window; preserve existing working sessions and never use their tasks for this matrix. Unit/VM coverage does not establish live Chromium behavior.

| Case | Action | Required evidence |
|---|---|---|
| No page | Keep the extension enabled with no ChatGPT tabs; query Doctor and open the known conversation | Fresh instance heartbeat, empty inventory, one background tab, canonical identity restored |
| Alias | Open by REF, query/retry the same operation by ID | Same operation and queue, no second tab |
| Project | Reopen a created Project chat and a previously observed manual Project chat | Correct Project route and canonical conversation binding |
| Reuse | Open a conversation with one existing tab | `page_reused`, same tab, no new message |
| Ambiguity | Open two copies of the target conversation; request Open and Close | Explicit refusal, neither tab modified |
| Draft | Add text, attachment or uploading attachment before Close | Refusal, all draft material preserved |
| Concurrent edit | Insert a draft or navigate after admission, before final close preflight | Refusal at the latest check, foreign page preserved; record any browser-level race limitations |
| Active work | Request Close during an active or recovering task and during page generation | Refusal, original task preserved, no Stop or resend |
| Close and reopen | Close an idle conversation with queued work, then Open it | Tab disappears, registry and queue remain, suspension survives; no dispatch until Continue |
| HTTP retry | Interrupt the agent HTTP response and retry the same operation ID | Same operation and at most one tab creation/removal |
| Lost checkpoint | Interrupt Open after native creation and before its tab checkpoint | Marked original tab observed or explicit unknown; never another create |
| Worker restart | Restart during queued/executing Open and Close | Old generations never mutate reused numeric tab IDs; observation or explicit unknown without replay |
| Script failure | Simulate an unreachable content script while the extension remains online | Fresh tab inventory, `script_unreachable`; Close and Refresh refuse |
| Instance loss | Disable the extension or disconnect Relay | Heartbeat becomes stale; no claim that the browser is definitely closed |
| Empty replacement | Close the last ChatGPT tab and read inventories repeatedly | Empty fresh inventory replaces prior tabs, delayed reports cannot resurrect them |
| Regression | Execute existing Refresh, Recover and Stop scenarios | Existing identity, draft protection and at-most-once send rules retained |

For every mutating case, retain the operation ID and final operation, page and queue observations. A queued operation or successful native API call alone is insufficient. Verify no new prompt is generated by Open, Close or recovery. Document whether the live check used the exact implementation revision.
